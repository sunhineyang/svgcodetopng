# SVG 实时颜色编辑功能 — 产品方案设计文档

## 1. 功能概述

### 1.1 一句话定义

在现有的 Settings 设置面板中新增一个「颜色」Tab，允许用户通过**色轮取色器**或**文本输入**两种方式快速替换 SVG 中的颜色，修改实时反映在预览区，且不影响编辑器中的原始代码。

### 1.2 核心价值

| 用户痛点 | 解决方案 |
|---------|---------|
| 拿着别人的 SVG 想换成自己品牌色，需要在代码里一个个找颜色值 | 自动提取 SVG 中的所有颜色，一键替换 |
| 直接改代码容易出错，改错了还要撤销重做 | 颜色编辑独立于代码编辑器，改坏了不影响原始代码 |
| HEX 色值不直观，不知道换成什么颜色好看 | 提供色轮取色器，可视化选色 |
| 想快速试几个配色方案对比效果 | 修改即时预览，支持「重置」回到原始状态 |

### 1.3 功能定位

- **类型**：辅助增强功能（v1 阶段非核心路径）
- **入口**：Settings 设置面板 → [颜色] Tab
- **前置条件**：用户切换到 SVG 模式且编辑器中有有效 SVG 代码
- **不涉及**：HTML/CSS 模式的颜色编辑（v1 阶段仅支持 SVG）

## 2. 用户体验设计

### 2.1 入口与交互流程

```
用户粘贴 SVG 代码
       ↓
预览区渲染 SVG（实时）
       ↓
用户点击「Settings」按钮
       ↓
Settings 面板展开
       ↓
用户点击 [颜色] Tab
       ↓
系统自动提取 SVG 中的颜色列表
       ↓
用户选择要修改的颜色（色轮 / 文本输入）
       ↓
预览区实时更新
       ↓
用户点击「应用并转换」或「下载」
```

### 2.4 组件详细设计

#### 2.4.1 颜色行（Color Row）

每个检测到的颜色对应一行。

```
┌──────────────────────────────────────────────────────┐
│ [色块]  原色值    [取色器]  [ HEX 输入框 ]  [应用]    │
│  40px   60px      32px      80px           60px      │
└──────────────────────────────────────────────────────┘
```

| 元素 | 说明 | 交互行为 |
|------|------|---------|
| **色块** | 显示当前颜色 | 点击可直接打开色轮取色器 |
| **原色值** | 显示原始 HEX 值 | 仅展示，不可编辑，作为参照 |
| **取色器按钮** | 打开色轮面板 | 点击展开色轮浮层 |
| **HEX 输入框** | 手动输入目标颜色 | 实时校验合法性（#开头 + 6位 HEX） |
| **应用按钮** | 将该颜色替换并预览 | 点击后该颜色在预览区更新 |

## 3. 功能逻辑设计

### 3.1 颜色提取规则

**提取范围**（v1）：

| SVG 属性 | 提取 | 示例 |
|---------|------|------|
| `fill` | ✅ | `fill="#3B82F6"` |
| `stroke` | ✅ | `stroke="#10B981"` |
| `stop-color`（渐变断点色） | ✅ | `<stop offset="0%" stop-color="#F59E0B"/>` |
| 渐变色（`url(#id)`） | ⚠️ 部分 | 提取渐变色定义中的 stop-color，渐变类型保留 |
| `currentColor` | ❌ 跳过 | 继承 CSS 的 currentColor，无法预知颜色 |
| CSS 内联 style | ✅ | `style="fill: #3B82F6"` |
| CSS class 中的颜色 | ❌ 跳过 | 需要额外解析，工作量较大 |
| 渐变 ID 引用 `url(#grad)` | ⚠️ 提示 | v1 阶段不支持替换渐变色，显示提示文案 |

**去重逻辑**：
- 大小写不敏感：`#3B82F6` 和 `#3b82f6` 视为同一颜色
- 相同颜色值只显示一行（去重）
- 最多显示 **10 个颜色**，超出时显示「检测到 {N} 个颜色，已显示前 10 个，请在代码中手动修改其他颜色」

### 3.2 颜色替换规则

**替换策略**：
- 替换 `fill` 属性中的颜色值
- 替换 `stroke` 属性中的颜色值
- 替换 `stop-color` 属性中的颜色值
- 替换 `style="fill: #xxx"` 和 `style="stroke: #xxx"` 内联样式中的颜色值
- 保留其他属性不变（如坐标、路径数据等）

**校验规则**：
- 输入必须是合法的 HEX 颜色（`#` + 3 或 6 位 HEX，可选带透明度的 8 位）
- 非合法输入时输入框边框变红，不执行替换
- 支持粘贴带 `#` 和不带 `#` 的输入

### 3.3 状态管理设计

**新增状态变量**：

```typescript
// 渲染用的 SVG 副本（颜色替换后的预览用）
const [renderedSvg, setRenderedSvg] = useState<string>(svgCode);

// 颜色映射：原始颜色 → 当前颜色
const [colorMappings, setColorMappings] = useState<Record<string, string>>({});

// 当前选中的替换目标色（用于快捷「替换全部」）
const [targetColor, setTargetColor] = useState<string>('#3B82F6');

// 颜色提取状态
const [extractedColors, setExtractedColors] = useState<string[]>([]);

// 是否处于颜色编辑模式（用于区分普通预览和颜色编辑预览）
const [isColorEdited, setIsColorEdited] = useState<boolean>(false);
```

**关键数据流**：

```
svgCode（原始代码，用户编辑）
      ↓
extractColors(svgCode) → extractedColors（自动提取）
      ↓
extractedColors + colorMappings → renderedSvg（替换后副本）
      ↓
dangerouslySetInnerHTML → 预览区渲染
      ↓
用户点击「转换」→ 使用 renderedSvg 执行转换
```

**重要**：颜色编辑后的 `renderedSvg` **不反向同步**到 `svgCode`，保证用户代码编辑器的独立性。

### 3.4 边界情况处理

| 场景 | 处理方式 |
|------|---------|
| 用户清空了编辑器 | 清空颜色列表，显示「请先输入 SVG 代码」 |
| SVG 无可提取的颜色 | 显示「未检测到可替换的颜色」 |
| 颜色超过 10 个 | 截断显示，提供提示文案 |
| 替换失败（如代码结构异常） | 显示错误提示，预览保持上一次成功状态 |
| 用户在颜色编辑后又去编辑器改了代码 | 自动检测代码变化 → 重新提取颜色 → 重置 colorMappings |
| 切换到 HTML/CSS 模式 | 隐藏「颜色」Tab 或显示「SVG 模式下可用」 |

## 11. FAQ（产品层面）

**Q：为什么不做成独立的「颜色编辑」页面？**
> 放在 Settings 面板内是最小改动方案。独立页面需要用户主动跳转，增加操作成本，且与「粘贴代码 → 转换 → 下载」的核心流程偏离。

**Q：为什么 v1 只支持 HEX，不支持 RGB / HSL？**
> HEX 是 SVG 中最常见的颜色表示法（占 90%+）。RGB/HSL 输入支持可以作为 v2 的小迭代。

**Q：预设色板的配色方案是怎么选的？**
> 基于以下原则：① 视觉设计师常用的 10-20 色调色板；② Tailwind CSS 默认色板的子集；③ 不包含过于极端或难看的颜色。

**Q：颜色修改会影响原始 SVG 代码吗？**
> 不会。颜色编辑使用的是 `renderedSvg`（渲染副本），原始 `svgCode` 状态不受影响。用户可以在任何时候回到原始代码继续编辑。

**Q：色轮取色器的体验如何保证？**
> 使用 `react-colorful`，该库支持暗色模式、与深色/浅色主题无缝融合，支持键盘输入 HEX 值，支持透明度滑块（可选开启）。
